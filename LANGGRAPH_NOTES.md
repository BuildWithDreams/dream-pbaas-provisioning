     Project Plan: LangGraph-Wrapped Ansible Playbooks for Deterministic Infrastructure Ops                                                                                                                                                 

```
     Key takeaways from the assessment:                                                                                                                                                                                                     
                                                                                                                                                                                                                                            
     - 85 playbooks covering the full lifecycle, 7 SPEC files, 11 runbooks — the project already has exceptional documentation. The gap isn't documentation or playbook quality; it's that the orchestration layer — which playbook, in     
     what order, with what params — is currently decided by LLM reasoning each time.                                                                                                                                                        
                                                                                                                                                                                                                                            
     - The recommendation is v1: Sync Status (a single-playbook, read-only graph in ~100 lines that validates the runner, state model, and output format) followed by v2: idcreate Deploy (a 6-7 playbook, multi-branch graph in ~300       
     lines that proves the pattern against your most complex real workflow).                                                                                                                                                                
                                                                                                                                                                                                                                            
     - The plan also catalogs 15 documented bugs from the ansible-provisioning skill — the LangGraph layer should encode pre-flight checks that catch these (like the -e @group_vars/production-local.yml flag check, or the caddy          
     read-only mount check) so they never hit you again.
```

     Assessment                                                                                                                                                                                                                             
                                                                                                                                                                                                                                            
     What exists today:                                                                                                                                                                                                                     
                                                                                                                                                                                                                                            
     The dream-pbaas-provisioning project is mature — ~85 numbered Ansible playbooks, 7 formal SPEC documents, 11 Jekyll runbooks, and a PLAYBOOK_CONVENTIONS.md that encodes every shared pattern (bootstrap logic, IP octet               
     assignments, Docker network topology, PBaaS hex IDs, Caddyfile management, compose naming). Each playbook is itself deterministic. The non-determinism comes from which playbook to run, when, and with what parameters —              
     decisions that currently require an LLM agent to reason over the full context each time.                                                                                                                                               
                                                                                                                                                                                                                                            
     The problem LangGraph solves:                                                                                                                                                                                                          
                                                                                                                                                                                                                                            
     LangGraph encodes the workflow as a state machine. Given the same input, the graph always traverses the same nodes in the same order. Conditionals are explicit edges, not LLM reasoning steps. This means:                            
                                                                                                                                                                                                                                            
     - The sequence is baked in — no agent has to recall the order of 39b → 40b → 41b → 42b                                                                                                                                                 
     - Decision points (has this been cloned already? Is the image stale? Is .env present?) are explicit state checks, not open-ended LLM deliberation                                                                                      
     - Error handling is a structured edge to a remediation node, not a "hmm, let me try something" prompt                                                                                                                                  
     - The user's role shifts from supervisor ("did you do the Caddy route yet?") to exception handler ("graph stopped at node verify_https because DNS hasn't propagated — investigate and resume")

     │                                                                │                                                                                                                                                                     
     │  Each node runs the actual playbook via:                       │                                                                                                                                                                     
     │    ansible-playbook -i inventory.ini playbooks/NN-*.yml        │

     Key principle: The graph never runs raw docker or ssh commands. Every action goes through a playbook. The playbook remains the source of truth for how to do something; LangGraph is the source of truth for when to do it and         
     what to do next.                                                                                                                                                                                                                       
     Recommended First Two LangGraph Versions                                                                                                                                                                                               
     v1: Sync Status (graph_sync_status)                                                                                                                                                                                                    
                                                                                                                                                                                                                                            
     Why this is the right first version:                                                                                                                                                                                                   
                                                                                                                                                                                                                                            
     1. Dead simple — One playbook (15-sync-status.yml or 15b-sync-status-vrsctest.yml). Pass chain name, run, parse output, return result. No branching, no preconditions, no state to manage.                                             
     2. High value — This is the most frequently run operation. Having a deterministic "how synced are we" answer that doesn't require an agent to interpret getinfo output is immediately useful.                                          
     3. Tests the infrastructure — Gets the LangGraph project scaffolded (project structure, state schema, node pattern, edge routing, ansible process spawning, output parsing) with minimal surface area.                                 
     4. Natural cron target — A cron-scheduled LangGraph run that checks sync and alerts on drift is the autonomous ops MVP.

     Implementation Principles                                                                                                                                                                                                              
                                                                                                                                                                                                                                            
     Principle: Playbooks are sacred                                                                                                                                                                                                        
     Rationale: The graph never bypasses a playbook. If a playbook doesn't exist for a step, the graph fails explicitly — it does NOT invent a raw SSH command                                                                              
     ────────────────────────────────────────                                                                                                                                                                                               
     Principle: Nodes are single-responsibility                                                                                                                                                                                             
     Rationale: Each node wraps one playbook (or one small group like clone+build for atomicity). If a playbook fails, the error is captured and surfaced, not silently retried by the LLM                                                  
     ────────────────────────────────────────                                                                                                                                                                                               
     Principle: State is explicit                                                                                                                                                                                                           
     Rationale: All decision state (cloned, built, deployed, routed) lives in the graph's typed state object, not in an LLM's ephemeral reasoning                                                                                           
     ────────────────────────────────────────                                                                                                                                                                                               
     Principle: Output is structured                                                                                                                                                                                                        
     Rationale: Every graph returns a typed summary dict — not prose — suitable for CLI display, cron delivery, or downstream automation                                                                                                    
     ────────────────────────────────────────                                                                                                                                                                                               
     Principle: Composability                                                                                                                                                                                                               
     Rationale: graph_idcreate_deploy should be usable as a sub-node inside a larger "full infra deploy" graph later                                                                                                                        
     ────────────────────────────────────────                                                                                                                                                                                               
     Principle: Learn from the bug log                                                                                                                                                                                                      
     Rationale: The ansible-provisioning skill has ~15 documented bugs (jinja2 * eval, None != '' truthiness, caddy read-only mount, compose blocking, etc.). The LangGraph layer should add pre-flight checks that catch these             
       before they happen, and structured error messages when they do
